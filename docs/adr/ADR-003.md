# ADR-003: Database — Neon PostgreSQL

**Context**: нужна managed Postgres с serverless-масштабированием и
дешёвым staging-окружением.

**Decision**: Neon PostgreSQL, с раздельными branch для production/staging.

**Reason**: branching даёт дешёвый staging (copy-on-write), встроенный pooler,
хорошо сочетается с Render (serverless backend + serverless DB).

**Trade-offs**: serverless "cold start"/connection limits требуют
обязательного pooling; vendor-специфичные фичи (branching) — не портируется
1:1 на "обычный" self-hosted Postgres без адаптации.
