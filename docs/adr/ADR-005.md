# ADR-005: Frontend state — TanStack Query (server) + Zustand (client) + RHF (forms)

**Context**: нужно разделить server state, UI state и form state, не
смешивая их в одном сторе.

**Decision**: TanStack Query для всего, что приходит с backend (каталог,
корзина, заказы); Zustand только для чисто клиентского UI-состояния;
React Hook Form + Zod для форм.

**Reason**: TanStack Query даёт кэш/инвалидацию/refetch из коробки —
не дублировать это вручную в Zustand. RHF+Zod даёт валидацию, близкую
к backend Pydantic-схемам по духу.

**Trade-offs**: два разных стейт-менеджера в проекте — команда должна
чётко понимать границу "что где хранится" (описано в ARCHITECTURE.md),
иначе возникнет дублирование состояния.
